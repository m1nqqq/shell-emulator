# Эмулятор оболочки ОС

Консольный эмулятор UNIX-подобной командной строки на Python.
Внешние зависимости не требуются, используется только стандартная
библиотека (Python 3.9+).

## Общее описание

Эмулятор ведёт диалог с пользователем в стиле командной строки
UNIX-подобной ОС: показывает приглашение, разбирает ввод и выполняет
команды. Поведение настраивается параметрами командной строки, а набор
команд выполняется как в интерактивном режиме, так и из стартового
скрипта.

Реализовано (этапы 1–3): REPL, параметры командной строки, стартовый
скрипт, отладочный вывод параметров, виртуальная файловая система (VFS)
из CSV-файла, сообщение motd, служебная команда `vfs-info`,
команды-заглушки `ls`, `cd` и `exit`.

## Функции и настройки

### Приглашение к вводу

Формируется из реальных данных ОС: `username@hostname:~$`
(`getpass.getuser()` и `socket.gethostname()`).

### Параметры командной строки

| Параметр        | Описание                                  |
|-----------------|-------------------------------------------|
| `--vfs PATH`    | Путь к CSV-файлу с VFS                    |
| `--script PATH` | Путь к стартовому скрипту                 |
| `-h`, `--help`  | Справка                                   |

Оба параметра необязательны. При запуске эмулятор выводит все заданные
параметры в формате «ключ = значение» (строки с префиксом `[debug]`);
незаданный параметр показывается как `<not set>`.

Коды завершения: `0` — штатное завершение, `1` — не удалось загрузить
VFS или прочитать стартовый скрипт, `2` — неверные параметры командной
строки.

### Стартовый скрипт

Текстовый файл в кодировке UTF-8, по одной команде эмулятора в строке.

- Строка, начинающаяся с `#`, — комментарий. Комментарий может стоять и
  в конце строки после команды: `cd docs  # перейти`.
- Пустые строки пропускаются.
- Каждая команда показывается на экране после приглашения, затем её
  вывод — как в настоящем диалоге с пользователем.
- Если команда завершилась ошибкой, выводится сообщение команды и строка
  `script error: line N: command failed`; выполнение скрипта продолжается.
- Команда `exit` завершает работу эмулятора (остаток скрипта
  не выполняется). Если скрипт закончился без `exit`, эмулятор переходит
  в интерактивный режим.
- Если файл скрипта не найден или не читается, выводится
  `error: cannot read startup script ...` и эмулятор завершается с кодом 1.

### Виртуальная файловая система (VFS)

VFS загружается из CSV-файла (`--vfs`) **целиком в оперативную память**.
Исходный файл только читается: ничего не распаковывается и не
изменяется. Без `--vfs` используется пустая VFS (только корень `/`).

Формат файла — CSV (UTF-8) с обязательным заголовком:

```
path,type,encoding,content
```

| Колонка    | Значение                                                        |
|------------|-----------------------------------------------------------------|
| `path`     | Абсолютный путь элемента, например `/home/user/notes.txt`       |
| `type`     | `dir` — каталог, `file` — файл                                  |
| `encoding` | Для файла `text` (по умолчанию) или `base64`; для каталога пусто |
| `content`  | Содержимое файла; для каталога пусто                            |

Вложенность задаётся полным путём: элемент `/a/b/c.txt` лежит в каталоге
`/a/b`, который лежит в `/a`. Недостающие родительские каталоги создаются
автоматически, поэтому строки `dir` нужны только для пустых каталогов.
Текст с переводами строк записывается в двойных кавычках (стандартное
правило CSV). Двоичные данные хранятся в `base64`.

Пример:

```
path,type,encoding,content
/motd,file,text,Добро пожаловать!
/docs,dir,,
/docs/readme.txt,file,text,Текстовый файл
/bin/logo.bin,file,base64,iVBORw0KGgo=
```

**motd.** Если в корне VFS есть файл `/motd`, его текст выводится при
запуске (после отладочного вывода параметров).

**Ошибки загрузки.** Эмулятор выводит `error: cannot load VFS: ...` и
завершается с кодом 1, если файл не найден или не читается, файл пуст,
заголовок не совпадает с `path,type,encoding,content`, в строке не 4
колонки, неизвестен тип или кодировка, данные `base64` некорректны, путь
не абсолютный, путь повторяется, а также если файл используется как
каталог. Для ошибок в строке указывается её номер (`row N`).

Готовые примеры лежат в `scripts/vfs/` (`minimal.csv`, `files.csv`,
`deep.csv`), некорректные — в `scripts/vfs/invalid/`.

### Команды

| Команда | Описание                                           |
|---------|----------------------------------------------------|
| `ls`       | Заглушка: выводит своё имя и аргументы          |
| `cd`       | Заглушка: выводит своё имя и аргументы          |
| `vfs-info` | Служебная: источник, число каталогов и файлов, размер |
| `exit`     | Завершает работу эмулятора                      |

Неизвестная команда: `unknown command: <имя>`. Ctrl+C отменяет ввод
строки, Ctrl+D (Ctrl+Z и Enter в Windows) завершает работу.

## Структура репозитория

```
src/            исходный код (main.py, shell.py, commands.py, vfs.py)
tests/          автоматические тесты (unittest)
scripts/        скрипты реальной ОС для проверки эмулятора (.bat)
scripts/startup/ стартовые скрипты эмулятора
scripts/vfs/    файлы VFS для проверок
run.bat, run.sh скрипты запуска эмулятора
```

## Сборка и запуск тестов

Сборка не требуется. Запуск автоматических тестов (из корня проекта):

```
python -m unittest discover -s tests
```

Скрипты реальной ОС (Windows), вызывающие эмулятор с разными параметрами:

```
scripts\test_stage2_basic.bat      параметры --vfs и --script
scripts\test_stage2_paths.bat      разные формы записи путей
scripts\test_stage2_errors.bat     ошибки параметров и скрипта
scripts\test_stage3_variants.bat   три варианта VFS + стартовый скрипт
scripts\test_stage3_motd.bat       motd и vfs-info для трёх вариантов VFS
scripts\test_stage3_errors.bat     ошибки загрузки VFS
```

Стартовый скрипт `scripts/startup/stage3_all.txt` проверяет все команды
этапов 1–3, включая работу с VFS и обработку ошибок.

## Запуск

```
run.bat                    # Windows
./run.sh                   # Linux / macOS
python src/main.py --vfs scripts/vfs/files.csv --script scripts/startup/stage3_all.txt
```

## Примеры использования

Интерактивный режим:

```
> python src/main.py
[debug] startup parameters:
[debug]   vfs = <not set>
[debug]   script = <not set>
user@host:~$ ls -l /tmp
ls: args = ['-l', '/tmp']
user@host:~$ foo
unknown command: foo
user@host:~$ exit
```

Запуск с VFS (выводится motd, затем сведения командой `vfs-info`):

```
> python src/main.py --vfs scripts/vfs/files.csv
[debug] startup parameters:
[debug]   vfs = scripts/vfs/files.csv
[debug]   script = <not set>
Welcome to the demo VFS!
Type 'ls' to look around.
user@host:~$ vfs-info
source: scripts/vfs/files.csv
directories: 1
files: 7
total size: 145 bytes
user@host:~$ exit
```

Ошибка загрузки VFS:

```
> python src/main.py --vfs scripts/vfs/missing.csv
error: cannot load VFS: file not found: scripts/vfs/missing.csv
```

Стартовый скрипт `scripts/startup/stage2_errors.txt`:

```
> python src/main.py --script scripts/startup/stage2_errors.txt
[debug] startup parameters:
[debug]   vfs = <not set>
[debug]   script = scripts/startup/stage2_errors.txt
# Скрипт с ошибками: эмулятор сообщает об ошибке и продолжает работу.
user@host:~$ ls
ls: args = []
user@host:~$ foo bar
unknown command: foo
script error: line 3: command failed
user@host:~$ exit
```
